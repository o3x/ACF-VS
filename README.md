# ACF-VS (Anime Cut Folder Versioning System)

アニメーション制作の撮影工程（Compositing）向けの、ハッシュベースの軽量なフォルダー状態記録ツールです。コマンドライン（CLI）と、Windows 用の PowerShell GUI（`acvs_gui.ps1`）があります。

> **現状（v0.4.8 / `redesign` ブランチ）：** 新設計に基づくプロトタイプ（`acfvs_cli.py` / `acfvs/`）を実装し、実際のカット構成に合わせて試作・改善中です。現行版（`acvs_core.py`）も互換テスト付きで維持しています。

## 1. ACF-VS とは（解決したい課題）

アニメ制作では 1 つの「カットフォルダー」の中に、Photoshop（BG）、Paint（CELL）、3D 素材、After Effects プロジェクトなど多数のファイルが入ります。作業者間でデータをやり取りするとき、古いファイルを `(old)` サブフォルダーに移して整理する運用がよく行われますが、「どのファイルが、いつ、新しいものに差し替わったか」が分からなくなる事故が起きがちです。

Git のようなソースコード用のバージョン管理は、数 GB のバイナリや数千枚の連番画像の履歴を抱えると破綻します。

ACF-VS は、ファイルの実体を保存せず、**「ファイルの指紋（ハッシュ）と場所の状態」だけを記録**します。実体のコピーを持たないので、巨大な素材フォルダーでも、状態の比較を数秒〜数分で行えます。

**できないこと**（誤解しやすいので先に書きます）:

- ファイルの中身は保存しないので、**古い版の復元はできません**。どの版だったかが分かるだけです
- ファイルを動かしたり、消したり、複製したりはしません（記録と表示だけ。読むだけです）
- **「誰が変えたか」は記録しません。** 履歴にあるのは時刻だけです

---

## 2. 主な機能

- **ハッシュベースの同一性判定**: ファイル名が変わっても、中身が同じなら同じファイルとして追跡します。差分は次の種別で表示されます
  - `[NEW]` 新規作成 ／ `[UPDATED]` 内容の更新 ／ `[DELETED]` 削除 ／ `[MOVED]` 場所・名前の変更
- **`(old)` へのアーカイブ認識**: ファイルが `(old)` を含むパスへ移されると、「削除と新規」ではなく `[ARCHIVED (old)]` として認識します（大文字小文字は区別しません）
- **高速モード（`--fast`）**: 巨大な PSD や AEP のために、中身を読まず「サイズ＋更新日時」だけで判定します
- **連番画像のグループ化（`--seq`）**: `A_cell_0001.tga` 〜 `1000.tga` のような連番（4 桁以上・2 枚以上）を、`A_cell_[0001-1000].tga` という 1 つの項目にまとめます
- **重複の警告**: 同じハッシュのファイルが別の場所にもあると `[DUPLICATE]` と警告します
- **履歴と比較**: コミットのたびに全体の状態を保存します。過去の任意の時点と現在、または過去 2 点を比較できます

## 3. インストールと準備

追加のライブラリ（`pip install` など）は不要です。Python の標準ライブラリだけで動きます。

**必要な環境**

- Python 3.10 以上（パスが通っていること）
- Windows 10 / 11（GUI を使う場合。CLI は OS を問いません）

**手順**

```bash
git clone https://github.com/o3x/ACF-VS.git
cd ACF-VS
```

作業しやすい場所にフォルダーごと置いてください。

## 4. GUI の使い方（Windows）

### 起動

エクスプローラーで `acvs_gui.ps1` を右クリックし、「PowerShell で実行」を選びます（またはターミナルから `.\acvs_gui.ps1`）。

### 画面

- **エピソードルート（Root Dir）**: カットフォルダーが並んでいる親フォルダーを「参照...」で指定します（参照ダイアログは、Windows の仕様でファイル選択の形をしていますが、フォルダーを選ぶためのものです）
- **カット番号**: 対象のカットフォルダー名を入力します（例: `c001`）。初期値の `test_env` は検証用です
- **Scan (Status)**（Enter キーでも実行）: 前回の記録と比べて「いま何が変わっているか」を表示します。記録は更新しません
- **Commit (Save)**: いまの状態を新しい基準として保存し、履歴に残します。変化が無ければ何もしません
- **History Log**: コミットの履歴を一覧します
- **Diff (Compare)**: 履歴一覧で 0〜2 件を選んで比較します（0 件: 最新の履歴と現在／1 件: その時点と現在／2 件: その 2 点）
- **Fast Mode / Group Seq Images**: 通常は両方オンです
- **プログレスバー**: 走査の進み具合を表示します
- **自動初期化**: 専用の Init ボタンはありません。未管理のフォルダーで操作すると、初期化するかを確認するダイアログが出ます

## 5. コマンドラインの使い方

各カットフォルダーを `--dir` で指定して、`acvs_core.py` を実行します。

```bash
# 管理を始める（.cut_manifest.json を作る）
python acvs_core.py init --dir <カットフォルダー> --fast --seq

# 前回の記録との差分を見る（記録しない）。scan / verify は同じ動作
python acvs_core.py status --dir <カットフォルダー> --fast --seq

# いまの状態を記録する（履歴に残る）
python acvs_core.py commit --dir <カットフォルダー> --fast --seq

# 履歴の一覧
python acvs_core.py log --dir <カットフォルダー>

# 過去との比較（--target は 0〜2 個）
python acvs_core.py diff --dir <カットフォルダー> --fast --seq --target 20260227_182939
```

**注意:** `--fast` の有無を途中で切り替えると、記録の形が違うため、全ファイルが `[UPDATED]` と出ます。同じカットでは同じオプションを使い続けてください。

## 6. 動作の仕組み（管理ファイル）

対象フォルダーの中に、次の隠しファイル・フォルダーを作ります。

- **`.cut_manifest.json`**: 最新の状態（全ファイルの一覧と指紋）。形式は [MANIFEST_SPEC.md](MANIFEST_SPEC.md) に書いてあります
- **`.acvs_history/`**: コミットのたびに、その時点の全状態を `日時.json` として保存します。差分ではなく毎回全体を持つので、1 件が壊れても他に響きません

記録は対象フォルダーの中に作られます。そのため、書き込めない場所（読み取り専用の共有など）は管理できません。

## 7. 現状と制約

現行版（0.3.3）には、一時フォルダーで再現して確認した、次の制約があります。

| 制約 | 内容 |
|---|---|
| 連番への追加が別物扱い | 連番に 1 枚足すと、`A_[0001-0003].tga` が `[DELETED]`、`A_[0001-0004].tga` が `[NEW]` と出ます |
| 無関係なファイルが重複と出る | `--fast` では、サイズと更新日時が同じだけで同じ指紋になるため、中身が違っても `[DUPLICATE]` と出ることがあります |
| `--fast` の切り替えで全件更新扱い | 上の注意のとおりです |
| 未初期化でも終了コードが 0 | スクリプトから呼ぶ場合、成否は出力の文字列で判断するしかありません |
| 記録の単位が、カットフォルダー 1 つ | 話数まるごと、一部分だけ、届いたフォルダーとの照合、は同じ仕組みでできません |

**再設計の向き**（たたき台。決まったことと仮置きは文書の中で区別してあります）:
「commit で区切って記録する」から、「いつでも・何度でも、見たままを記録する（観測）」へ。記録するのは事実だけにして、`(old)`・連番・移動といった解釈は、読むときに規則で付ける。同じかどうかは、証拠の強さを付けて言う。他のアプリから使いやすいよう、形式・コマンド（JSON）・ライブラリの三つの口を用意する。
詳しくは [docs/261116_再設計_設計思想.md](docs/261116_再設計_設計思想.md)。形式は、再設計で置き換わる見込みです（まだ運用に入っていないため、互換は考えていません）。

## 8. テスト

現行版の特性テスト 15 本と、再設計プロトタイプ（`acfvs`）のテスト 10 本の計 25 本があります。

```bash
python -m unittest discover -s tests -v
```

### 再設計プロトタイプ（v0.4.8）の使い方

Python 標準ライブラリのみ（`tkinter` 含む）で動作します。

```bash
# デスクトップ GUI を起動（カット構成マップ・スロット×塊俯瞰・塊比較・関連付けアプリ起動・履歴・工程メモ）
python acfvs_cli.py gui

# CLI: スロット×塊単位の現在地俯瞰（--json で機械向け出力）
python acfvs_cli.py inspect --dir <カットフォルダー> --slots

# CLI: 観測の記録 / 比較 / 工程メモ
python acfvs_cli.py observe --dir <カットフォルダー> --note "朝イチ確認"
python acfvs_cli.py compare --dir <カットフォルダー>
python acfvs_cli.py note --dir <カットフォルダー> --unit c0000 --status 撮影中 --comment "BG差し替え反映"
python acfvs_cli.py list --dir <カットフォルダー>
```

- **台帳の置き場（`--ledger` / GUI の「台帳(任意)」）**: 空欄時は対象フォルダー内の `.acfvs/` を使用します。外部フォルダーを指定すると、元の制作フォルダーを汚さずに観測（`observations/*.jsonl`）と工程メモ（`notes.jsonl`）を記録できます。
- **作品プロファイル（`acfvs_profile.json`）**: 作品ごとにカット内のスロット構成（`CELL` / `BG` / `3D` / `2D` / `FX` / `TS` 等）が異なる場合は、台帳内または対象フォルダー直下に配置して上書きできます。

手元で挙動を試すには、ダミーの連番環境も作れます。

```bash
python test_seq_generator.py --dir test_env --count 1000
python acvs_core.py init --dir test_env --fast --seq
# ファイルを足す・更新する・(old) へ移すなどして、status / commit / diff を試す
```
