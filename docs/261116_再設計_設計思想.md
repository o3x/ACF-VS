## 2. 問題の掘り起こし

現行（0.3.3）の個々の不具合（連番に 1 枚足すと削除＋新規になる、Fast Mode で無関係なファイルが重複と出る、など）は、症状。その下にある取り違えを、望の見立てとして 6 つ挙げる。**どれも【仮置き】で、大山さんの実感と合わなければ直す。**

### 根 1：Git の写しになっている

`init`・`status`・`commit`・`log`・`diff` は Git の言葉。Git は「人が区切りを付けて記録する」ことを前提にしている。
撮影の現場では、ファイルは道具の外で、いろいろな人とアプリによって変わる。届く、差し替える、`(old)` に移す。そのたびに誰かが commit することは、期待できない。
**記録する行為を人に求める設計は、導入した日から穴が開く。** 必要なのは「区切りを付ける」ではなく「見たままを残す」こと。

### 根 2：単位が「カットフォルダー 1 つ」に固定されている

記録（`.cut_manifest.json`）がカットフォルダーの中に 1 つ。だから、話数まるごと、カットの一部（`CELL` だけ）、届いたフォルダー、`Common` を、同じ仕組みで扱えない。
さらに、記録を対象のフォルダーの中に書くので、書き込めない場所（サーバーの読み取り専用、他社から届いたデータ）は対象にできない。

### 根 3：事実と解釈が混ざって記録されている

- `is_archived`（`(old)` を含むか）は、流儀にもとづく**解釈**。それを記録に焼き込んでいる。流儀が変わると、過去の記録が嘘になる
- 連番のキー `A_[0001-0003].tga` は、まとめ方という**見せ方**。それを項目の名前にしている。だから 1 枚増えると別物になる
- 「移動」「更新」「アーカイブ」は、二つの状態を比べたときの**解釈**

記録に残すべきは事実（どこに・何が・どんな中身で在ったか）だけ。

### 根 4：「同じファイルか」の証拠の強さが混ざっている

「サイズと更新日時が同じ」と「中身のハッシュが同じ」は、証拠の強さがまるで違う。現行は、これを同じ `hash` という欄に入れ、同じ重みで「移動」「重複」を言う。しかも形式が 3 つあって、互いに比べられない。
更新日時は、コピー・展開・FTP で変わりうる。受け渡しの前後を照合する場面で、いちばん当てにならない。

### 根 5：人が読む文字列が、唯一の出口になっている

結果は標準出力の英文だけ。GUI はそれを正規表現で読む。終了コードは失敗でも 0。
ほかのアプリが乗り入れる口が無い。

### 根 6：「誰が」が無い。そして、原理的に分からないことがある

記録にあるのは時刻だけ。
ただし、正直に書くと、**ファイルシステムからは「誰が変えたか」は分からない**。分かるのは「誰が・いつ・どのマシンから見たら、こうだった」まで。「誰が変えたか」は、観測と観測のあいだに起きたこととして絞り込むか、人が書き添えるしかない。道具が分からないことを、分かるふりをしない。

## 3. 設計思想（原則）

### P1　核は、ファイルに触れない【仮置き：現行から引き継ぐ案】

核は読むだけ。動かさない・消さない・複製しない。
全体として、ファイルを動かす層（配る・集める・並べ直す）を持つかは【未決】（9 の 1）。持つとしても別の層に作り、この核の「見る力」を使う、というのが望の案。

### P2　中心に置くのは「観測」【仮置き】

> いつ・誰が・どのマシンから・どこを見たら・こうだった

これを一つの単位にする。commit ではない。**観測は、いつ・何度取ってもよい。取っても何も変わらない。**
人が手で取ってもよいし、ほかのアプリが節目（届いた・上げた・開いた）で取ってもよいし、定時に取ってもよい。
「履歴」は観測の列。「現在の状態」はいま取った観測。「過去の状態」は昔の観測。

### P3　記録するのは事実だけ。解釈は、読むときに付ける【仮置き】

観測に書くのは、相対パス・サイズ・更新日時・中身の指紋。
「移動した」「古い版に回した」「連番である」「このカットの `BG` である」は、読むときに規則を当てて出す。
規則を直せば、過去の観測も新しい規則で読み直せる。

### P4　同一性は、証拠の強さを付けて言う【仮置き】

「同じ（中身で確認）」「同じらしい（サイズと日時）」「違う」を区別して出す。
速さは、形式を変えるのではなく、**計算済みの指紋を覚えておく**ことで得る（場所・サイズ・日時が変わっていなければ、前に計算した指紋を使う）。
Fast Mode は「別の形式」ではなく「どこまで確かめるか」の選択になる。

【未決】覚えていた指紋を使った項目は、今回は中身を読んでいない。項目ごとに「今回読んで確かめた／前の計算を引き継いだ」を記録に持つか。持たないと、「中身で確認」と言いながら実はサイズと日時しか見ていない、が起きる。望の推しは、持つ。

### P5　単位を決め打ちしない【仮置き】

観測の対象は、どのフォルダーでもよい（カット、話数、`Common`、届いたフォルダー、一部分）。
比べるときは、**ある観測の中の一部分**と**別の観測の全体**を突き合わせられる（話数の観測の中のカット 1 つ ⇔ 届いたフォルダー）。
「カット」「話数」は、パスに規則を当てて付ける名札。核は、名札を知らない。

### P6　正は、追記するだけの素朴なファイル【仮置き】

- 観測は 1 つ 1 ファイル。書いたら変えない。足すだけ
- 複数のマシンから同じ置き場に書いても、ぶつからない（ファイル名が時刻＋マシン＋乱数）
- 速く引くための索引（データベースなど）は持ってよいが、**観測のファイルから作り直せるもの**に限る
- 書くときは、一時ファイルに書いてから名前を変える（途中で落ちても壊れた記録が残らない）

ネットワークドライブの上にデータベースを正として置かない。壊れたときに直せるのは、素朴なファイルだけ。

### P7　乗り入れ口は三つ【仮置き】

| 口 | 相手 | 約束 |
|---|---|---|
| 形式 | 観測のファイルを直接読むアプリ（AE のスクリプトなど） | 仕様書と版番号。知らない項目は無視すれば読める |
| コマンド | ほかのアプリ・スクリプト | 結果は JSON、成否は終了コード。人向けの表示は別の出口 |
| ライブラリ | Python から呼ぶアプリ | 走査・照合・問い合わせの関数 |

人が読む文字列を、機械に読ませない。

### P8　現場の流儀は、設定に出す【仮置き】

`(old)`、連番の桁数、除外するもの、フォルダーの名前とカット・話数の対応。核に直書きしない。
設定が無くても、事実の記録と照合は動く。設定は、解釈を足すだけ。

### P9　核は小さく、動詞は三つ【仮置き】

1. **観る**：フォルダーを走査して、観測を 1 つ書く
2. **比べる**：二つの状態（観測どうし、または、いまのフォルダー）を突き合わせる
3. **引く**：観測の一覧、ある項目の経歴、ある中身がどこに在るか

これ以外（画面、伝票、通知、配る・集める）は、核の外。

## 4. 核のモデル（仮置き）

### 4.1 観測

```json
{"kind": "observation", "format": "2.0", "id": "20261116T113331Z-HOSTNAME-a3f9",
 "taken_at": "2026-11-16T20:33:31+09:00",
 "observer": {"user": "…", "host": "…", "tool": "acfvs 1.0.0"},
 "root": {"path_as_seen": "\\\\server\\proj\\ep01", "label": "…"},
 "scope": {"subpath": "", "exclude": ["…"]},
 "depth": "content", "note": "…", "trigger": "manual"}
{"path": "c001/BG/bg.psd", "size": 1048576, "mtime": "2026-11-15T09:12:00.5Z", "sha256": "8ae4…"}
{"path": "c001/CELL/A/A_0001.tga", "size": 419430, "mtime": "…", "sha256": "…"}
```

- 1 行目が観測そのものの情報、2 行目から 1 行 1 項目（数十万項目でも、少しずつ読める）
- 時刻は、時差つきで書く（複数のマシン・拠点で混ざらない）
- `depth`：どこまで確かめたか（`stat`＝サイズと日時だけ／`content`＝中身の指紋まで）
- `note`・`trigger`：人のひとこと・きっかけ（手動／届いた／上げた／定時 など）
- 指紋は、方式の名前を付けて持つ（方式を変えても、古い記録が読める）
- パスは `/` 区切りの相対パス。文字の正規化（Mac と Windows の濁点の違い）と大文字・小文字は、比べるときにそろえる

### 4.2 連番

連番も、**事実としては 1 枚 1 項目**で記録する（どのコマが変わったかを言えるようにするため）。
「連番 1 つ」にまとめるのは、読むとき・見せるとき。連番の身元は「フォルダー＋前の文字＋拡張子」で、**コマの範囲は身元に入れない**。
だから、1 枚足したら「`A_####.tga`：3 枚 → 4 枚（1 枚追加）」と言える。

【未決】数十万枚の規模で、1 枚 1 行の観測が重すぎないか（実測する）。重ければ、連番をまとめた行（コマの表つき）を形式に足す。

### 4.3 照合

入力は二つの状態。出力は、項目ごとの関係と、その証拠の強さ。

| 関係 | 意味 |
|---|---|
| 同じ | 同じ場所に、同じ中身 |
| 変わった | 同じ場所で、中身が違う |
| 移った | 同じ中身が、別の場所に（名前の変更を含む） |
| 増えた／消えた | 相手に無い |
| 写しがある | 同じ中身が、複数の場所に |

「古い版に回した」は、「移った」に規則（`(old)`）を当てた解釈。
片方が `stat` だけの観測なら、結果は「同じらしい」止まりで、そのことを結果に書く。

### 4.4 名札（規則による解釈）

設定の例（形は未決）:

```json
{"archive": ["(old)"],
 "sequence": {"min_digits": 4, "min_count": 2},
 "units": [{"name": "cut", "pattern": "{cut}/**"}, {"name": "kind", "pattern": "{cut}/{kind}/**"}],
 "exclude": [".git", "Thumbs.db"]}
```

### 4.5 置き場

【未決】観測のファイルをどこに置くか。

| 案 | 良い点 | 困る点 |
|---|---|---|
| 対象のフォルダーの中（いまの方式） | フォルダーごと持ち運べる。カットで自己完結 | 書けない場所は見られない。納品物に混ざる |
| 外の台帳（決めたフォルダー） | どこでも見られる。話数・作品をまたいで引ける | フォルダーと記録が別々になる |
| どちらも選べる（形式は同じ） | 場面で使い分け | 説明が一つ増える |

望の推しは三つ目。形式が同じなら、核は置き場を知らなくてよい。

### 4.6 場所の身元と、観測が覆う範囲【未決】

答え 2（絨毯的・部分的、現在・過去）にいちばん効く所で、まだ解けていない。

- **同じフォルダーが、マシンごとに違うパスで見える**（`\\server\proj\ep01`、`P:\ep01`、Mac の `/Volumes/…`）。パスを身元にすると、同じ場所の観測がつながらない
- **観測ごとに、覆う範囲が違う**。月曜は話数まるごと、火曜は `c001/CELL` だけ。「最後の観測 ⇔ いま」「3 日前のこのカット」は、その場所を覆っている観測を選んで、その一部分を取り出して出すことになる

案:

| 案 | 中身 | 困る点 |
|---|---|---|
| 名前を人が付ける | 置き場の設定に「この名前＝このマシンではこのパス」を書く | マシンごとに設定が要る |
| 場所に印を置く | 根のフォルダーに小さな身元ファイルを 1 つ置く | 書けない場所には置けない（P1 とも当たる） |
| 中身から推す | 観測どうしで、中身の重なりが大きければ同じ場所とみなす | 推定なので、外れることがある |

置き場（4.5）をフォルダーの中にすれば身元は自明になるので、4.5 と一緒に決める。
観測は、自分が覆った範囲（根の名前＋その中のどの部分＋除いたもの）を必ず書く。覆っていない所について「消えた」と言わないため。

### 4.7 あとから書き添える【未決】

観測は書いたら変えない（P6）。一方で、「この差し替えは〇〇さん」「これは誤って上書きした」を、あとから人やほかのアプリが書き添えたい（根 6）。

- 案 A：観測とは別の種類の、追記するだけの記録（覚え書き）を持つ。どの観測・どの項目についてかを指す
- 案 B：書き添えは持たない。観測を取るときのひとことだけ。あとからの話は、乗り入れる側（進捗管理など）が自分で持つ

案 A は、ほかのアプリが「書く」側の乗り入れ口にもなる。最初の版は案 B で始めて、形式に余地だけ残す、が望の推し。

## 5. 層

```
 ┌──────────────────────────────────────────────────────┐
 │ 乗り入れるもの：画面／進捗管理アプリ／AE のスクリプト  │
 │ ／配る・集める道具／受け渡しの伝票                     │

 ├──────────────────────────────────────────────────────┤
 │ 解釈：名札・連番・(old)（設定で決まる。読むときに付く）│
 ├──────────────────────────────────────────────────────┤
 │ 核：観る・比べる・引く                                 │
 ├──────────────────────────────────────────────────────┤
 │ 形式：観測のファイル（追記だけ。仕様書と版番号）       │
 └──────────────────────────────────────────────────────┘
```

下の層ほど、変えない。上の層ほど、取り替えてよい。

## 6. 「多様な見方」は、どう出るか

| 見たいこと | 核の言葉で |
|---|---|
| このカットは、前に見たときから何が変わったか | 最後の観測 ⇔ いま |
| 話数まるごと、今週なにが動いたか | 月曜の観測 ⇔ いま（カットの名札でまとめて表示） |
| `CELL` だけ見たい | 観測の一部分どうしを比べる |
| 3 日前、このカットはどうだったか | その日の観測を引く |
| 届いたデータは、手元の何と同じで、何が新しいか | 届いたフォルダーの観測 ⇔ カット（または話数）の観測 |
| 送ったものは、向こうに着いたものと同じか | 送る前の観測 ⇔ 着いた先の観測（中身の指紋） |
| このファイルは、いつ `(old)` に回ったか | 項目の経歴を引く（中身の指紋でたどる） |
| 同じものがあちこちに無いか | 写しを引く |

「誰が変えたか」は、この表に無い（根 6）。出せるのは「この観測とこの観測のあいだ」と、観測に添えたひとこと。

## 7. やらないこと【仮置き】

- ファイルの中身を保存しない。だから、復元はできない（どの版だったかは言える）
- ファイルを動かさない・同期しない
- 進捗（IN・UP・チェック）を持たない。それは進捗管理の側の仕事
- 常駐して監視しない（最初の版では。節目で観る）

---

## 8. 最初の版に入れるもの【仮置き】

1. 形式の仕様書（観測のファイル）
2. 観る（`stat`／`content`、計算済みの指紋を覚える、進み具合を出す、読めないファイルは飛ばして記録する）
3. 比べる（観測 ⇔ 観測、観測 ⇔ いま、一部分どうし。結果は JSON と、人向けの表示）
4. 引く（観測の一覧）
5. 解釈は `(old)` と連番だけ
6. テスト（照合の表を、小さな作り物のフォルダーで全部通す。**同じ中身のファイルが多数ある場合**——空のコマ・止めの連番——で、「移った／写しがある」が多対多になってどう出るかも確かめる）

画面は、核が固まってから。Python の標準ライブラリだけで作る（配るときに、入れるものを増やさない）【仮置き：現行から引き継ぐ案】。

現行から引き継ぐもの：ファイルに触れない／中身を持たず指紋だけ／各観測が全体を持つ（差分でつながない）／`(old)` と連番という現場の見方。
捨てるもの：Git の言葉（init・commit）／記録に焼き込んだ解釈／3 つの指紋の形式／標準出力の文字列を読む GUI。

## 9. 大山さんに聞きたいこと【未決】

1. **「包括的なファイル群の管理システム」の範囲。** 核は「見る（観測と照合）」だけで、動かす道具はその上に別に作る、という分け方で合っているか。それとも、最初から動かすところまでが一つの道具か
2. **根 1 の見立て。**「記録する行為を人に求めない。見たままを、いつでも・何度でも残す」は、現場の実感に合うか
3. **置き場（4.5）。** フォルダーの中／外の台帳／選べる
4. **試金石にする事故。** 現場で実際に起きた「分からなくなった」例を二つ三つ。設計がそれを見つけられるかで、案を確かめたい。あわせて、実際のフォルダーの並び（名前だけ）と、話数あたりのファイル数の規模
5. **場所の身元（4.6）と、あとから書き添える（4.7）。**
6. **名前。** 中心が「版の管理」から「観測と照合」に移る。ACF-VS の名前と「Versioning」を残すか
